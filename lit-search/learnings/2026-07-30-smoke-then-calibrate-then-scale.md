# 换 LLM 供应商：先冒烟、再校准、最后放量

**问题**：把一条已经跑通的 LLM 流水线从 Anthropic 换成 DeepSeek。
表面上只是换 `base_url` 和模型名，实际有两处会让整轮 1,234 个请求全部作废。

## approach

三级放量，每一级只花上一级的十倍钱，但能发现完全不同类型的问题。

1. **先查 API 形态，不靠记忆。** 拉官方定价页与文档，确认模型 ID、
   有没有批处理、结构化输出走什么形态、缓存怎么计费。结论直接改架构：
   没有 Batches API（半价没了）、没有 `count_tokens`（估算只能近似）、
   缓存自动生效（命中价差 120 倍，必须建模进估算）。
2. **选服务端校验的那条路。** DeepSeek 的 JSON 模式只保证"是合法 JSON"，
   不保证形状，官方还承认它偶尔返回空内容；strict 工具调用在服务端按 JSON Schema
   校验。选后者，代价是走 `/beta` 端点 + schema 必须手写（不能有 `$ref`，
   每层 `additionalProperties: false`，`required` 列全属性）。
3. **4 条记录冒烟（$0.003）→ 抓到 400。** `Thinking mode does not support this
   tool_choice`：V4 默认开思考，而思考模式拒绝一切强制 tool_choice。
   这类问题在单元测试里发现不了——假客户端不会替你复现服务端的约束。
4. **100 条校准（$0.05）→ 抓到协议与阶段的错配。** 人工队列 13%，
   查看后发现全是模型在等摘要给出 Dice/HD95，而那是全文阶段才有的东西。
   改提示词加入"这是标题摘要初筛"的阶段规则后：纳入 3→6，队列 13→11，
   且剩下的全是真分歧。
5. **全量放量。** 到这一步已经知道：单价、失败模式、队列规模都在预期内。

## 判断取舍

- **关掉思考模式，保住强制工具调用。** 初筛是照着 8 条明确标准做分类，
  思考的收益有限；而"每一批都拿得到可解析的判定"是刚需——拿不到就要人去看
  模型本来判得了的记录。反过来的取舍（开思考、放弃强制）留成显式参数。
- **修提示词而不是修协议。** 改 `criteria` 会变更协议语义指纹，挡住后续的
  滚雪球并入。而"这是初筛不是全文评估"本来就是**阶段**的属性，不是标准的属性，
  写进提示词才是它该待的地方。
- **试跑不占正式轮次。** `--limit` 的结果写 `screening_trial.json`，
  否则一次校准会盖掉全量结果，而下游只认轮次号最大的那一轮。
- **没有把估算改成"精确"。** 没有 `count_tokens` 端点就是没有，
  `precise` 恒为 False 并在输出里标注；真实用量跑完由 API 回报，两个数都打出来。

## 可复用的规则

**换供应商时，把"能不能跑通"和"跑得对不对"分成两次不同规模的实验，
中间留出改设计的机会。** 冒烟测试验证的是 API 契约（几美分），
校准测试验证的是任务设计（几毛钱），只有这两关都过了才谈放量。

推论：**假客户端测得了你的代码，测不了服务端的约束。**
思考模式与 tool_choice 互斥这种事，只有真发一次请求才知道——
所以冒烟测试不能省，也不该等到全量时才第一次接触真实 API。
