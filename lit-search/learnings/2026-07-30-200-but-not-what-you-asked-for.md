# HTTP 200 不代表拿到的是你要的东西

**问题**：用 doi.org 内容协商给 1,487 篇文献生成参考文献。请求 `Accept: text/x-bibliography`，
部分 DOI 解析到出版商落地页，**200 返回整页 HTML**——内容协商没被遵守。
88 段 HTML 以「已由出版商登记数据渲染」的身份写进了参考文献和 `.bib`。

## approach

1. **先承认这是旧错误的复发。** 阶段 3 早就立过规则：CVF「200 但解析出 0 篇」
   必须报失败。我在新代码里只挡了 JSON 错误（`{` 开头），因为那是我**当时唯一见过**的
   失败形态——把"见过的坏样本清单"当成了校验。
2. **把校验从"排除已知坏样本"改成"确认是要的格式"。** 抽出 `validate_citation`：
   空、JSON、HTML（`<` 开头 / `<!doctype` / `<html`）、超长、
   以及要 BibTeX 却不以 `@` 开头——任一条都判定为不是引文。
3. **降级要留痕。** 校验失败的记录落到本地渲染并标 ⚠️，
   数量在文档抬头和 `.bib` 注释里都写出来（47 条）。
4. **用一个跨格式的算术不变量兜底。** `已校验 + 已降级 == 总条数`。
   修之前这个式子对不上（1448 + 32 ≠ 1487），而**正是这个对不上暴露了污染**——
   HTML 里含空行，被 `\n\n` 切成了多块。

## 判断取舍

- **没有对返回 HTML 的 DOI 重试。** 那不是瞬时故障，是出版商不支持内容协商，
  重试一百次结果一样。
- **`.bib` 只写通过校验的条目。** 本地拼的引文字段不全，混进去会污染整个文件；
  宁可少 47 条并注明，不要一个"看起来完整"的 `.bib`。
- **HTML 实体反复解到稳定，最多 3 次。** Crossref 里有 `&amp;amp;` 这种双重转义，
  解一次不够；但无限解会把正文里真正的 `&amp;` 字面量也吃掉。
- **没有顺手加"清洗 HTML 取正文"的兜底。** 从落地页刮出来的引文没人核对过，
  它会长得和登记数据一模一样——这正是最危险的地方。

## 可复用的规则

**校验要写成"确认它是我要的"，不是"排除我见过的坏样本"。**
后者永远只覆盖你已经踩过的坑，而下一种失败形态一定长得不一样。

推论：**任何"内容协商"或"格式化输出"的接口，都要在解析前先断言格式。**
状态码只说明服务器愿意回应，不说明它回应了你问的问题。

推论二：**给每条流水线找一个跨阶段的算术不变量**（已校验 + 已降级 = 总数、
识别 − 去重 = 筛选输入）。它不会告诉你哪里错了，但它会在你以为一切正常时喊停。
