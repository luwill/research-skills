# 没有布尔检索能力的源，怎么保住召回边界

**问题**：系统检索要求"我查过什么、漏了什么"可回答。但有些源根本不支持
AND/OR——CVF 没有检索接口，OpenReview 和 Zenodo 只有单框检索且多词按 OR 处理。
把布尔串直接塞进去不会报错，会**静默返回上万条噪声的前几页**。

## approach

1. **先测每个源的失效方式，别照文档写。** 对每个源打三种查询：加引号的短语、
   不加引号的多词、单个泛词。看返回的 `count`。
   - OpenReview：`"ischemic stroke"` → 210；`ischemic stroke lesion segmentation`
     → 10000（就是返回上限）；`"segmentation"` → 10000。
   - 结论一眼可见：多词是 OR，且有硬上限。
2. **确定"锚点块"**。概念块里必有一个区分度最高（本例是疾病），
   其余是泛词（segmentation、deep learning）。只用锚点块的短语去检索，
   保证每条检索式结果集**有界、可翻完**；其余必需块在本地做 AND。
3. **把本地 AND 做成共享模块**，三个源复用同一个 matcher。术语编译成
   带词边界的正则，通配符只在词内展开，空格与连字符等价。
4. **只有标题可用时（CVF），门槛用必需块的并集，取回摘要后再用交集严格判。**
   标题里往往只写得下一个概念（"…Medical Image Segmentation" 不会再写
   "ischemic stroke"），用交集当门槛会漏掉一大片。
5. **枚举式源返回 200 却解析出 0 条，一律报 failed。** 先回索引页找有没有
   分页/逐日子页面，仍然为 0 就抛错。

## 判断取舍

- **没把 MeSH 词纳入本地匹配。** 受控词是给已建索引的库用的，当自由文本正则
  会悄悄放宽概念边界——本例里 MeSH 的 `Stroke` 会命中 CVPR 的"笔触"论文。
- **没有为了省事把任务块也当锚点。** 那样每条检索式都撞返回上限，
  等于回到"相关度排序的前 N 条"，整套设计失去意义。
- **没有在整卷补全时按概念块过滤。** 拿同卷兄弟篇正是那一步的目的；
  该不该纳入是筛选阶段的判断。事后证明这一步的独有贡献占比 97%。
- **没有把 CVF 的零结果当作"这个源没用"而删掉。** 花约 2,000 次请求
  证明"CVPR/ICCV/WACV 2021–2026 共 9,200 篇里一篇都没有"，
  与"我觉得那里没有"是两回事——前者能写进方法学，后者不能。

## 可复用的规则

**当一个数据源的"没有结果"和"我用错了它"长得一样时，先花几次请求把两者区分开，
再写一行代码。** 具体到检索：任何一条检索式，如果你说不出它的结果集有多大、
翻不翻得完，它就不能作为召回边界的一部分。

推论一：**返回 200 且结构合法、但解析出 0 条，默认判失败，不判空。**
空结果必须是被证明的，不是被假设的。

推论二：**能力弱的源不是靠"降低期望"来用，是靠把它的查询空间拆到它扛得住的粒度。**
一条打不完的宽查询，换成 12 条各自有界的窄查询。
