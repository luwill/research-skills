# 沉默的缺席

**问题**：审视一个已经"做完"的检索流水线，找出还能优化什么。
真正的发现不在代码里，在仓库角落一次真实运行的**产物**里——
它看起来完整，实际漏了三件事，而没有任何一份产物提到。

## approach

1. **先找这个工具自己跑出来的东西，别只读它的文档。**
   仓库里有两个 run 目录，第二个是主题完全不同的一次运行（生物医学 → 纯 CS）。
   换域运行是最好的测试用例：为原域调好的假设会在这里集体暴露。
2. **拿产物的内部一致性当探针。** 不去读代码猜哪里会错，而是问：
   manifest 声明了 4 个源，`outcomes` 里只有 2 个——这两个字段为什么对不上？
   顺着这一条线索挖出了续跑扩源的 bug、depth 未记录、以及报告里的硬编码假理由。
3. **自己复核 agent 的结论。** 并行派了三个 agent 查不同维度，
   但每条"严重"结论都自己跑命令验证过：
   `curl` 实测 arXiv DOI 在 Crossref 上 404、
   构造一份启用 `semantic_scholar` 的协议看它是否被静默丢弃。
   有一条 agent 的定位是错的（说源被过滤出表，实际是压根没执行），
   不复核就会修错地方。
4. **TDD，且测试要钉住"不许出现什么"。** 修硬编码那句话时，
   除了"缺席时点名真正缺的源"，还写了一条断言：
   "配额限制未纳入"这串字不得在无依据时出现。护栏要挡住**复发**，不只是当前这次。
5. **拿真实产物验收，不只看测试绿。** 把出问题的那个 run 复制到临时目录重跑 `report`，
   确认三个缺口真的印出来了。测试用的是构造数据，它证明不了"在那份真实的
   4,018 条语料上也对"。

## 判断取舍

- **没有把 Semantic Scholar 实现掉，而是三处文档改口说它不可用。**
  实现它要 key、要 bulk 翻页，是另一件事。
  但"推荐一个不存在的源"必须当场停掉——它的终点是向用户声称补上了覆盖面，
  而实际什么都没发生。**先止血，再补功能。**
- **没有替用户轮换 `.env` 里的真实密钥，只报告。**
  轮换要登录厂商控制台，是用户的动作；我能做的是确认它被 `.gitignore` 挡住、
  并把"当前还不是 git 仓库、打包分发会带上它"这个前提说清楚。
- **没有重跑原始 run 目录去覆盖旧产物。** 那是一次历史运行的记录。
  验证复制到 scratchpad 做。
- **SKILL.md 净增了行数，没有为了"瘦身"而删规则。**
  只把两段模型没有对应操作的内部论证挪进 `references/evidence.md`。
  正文变长是因为补上了原本缺失的可执行指令（`<run>` 从哪来、滚雪球循环怎么收）——
  一份读完不知道下一步敲什么的 skill，短也没用。

## 可复用的规则

**「跑了没成功」和「压根没跑」是两种失败，后者需要自己的表示形式。**

前者天然会留下痕迹（一条失败记录、一个告警），系统设计者一定会处理它。
后者的痕迹是**一个不存在的东西**，只能靠比对"声明了什么"和"做了什么"发现——
而没有人会去比对这两个字段。所以必须由系统主动算出差集、主动写进报告，
且**差集为空时也要写出"无"**：「无缺口」必须是结论，不能靠空白段落暗示。

推论一：**报告里任何一句解释"为什么某项没做"的话，都必须是算出来的。**
硬编码的缺席理由和算出来的长得一模一样，读者没有任何办法从报告本身发现它是假的。
它比没有解释更糟——没有解释至少会引发追问。

推论二：**换一个域跑一遍，是检验假设最便宜的方式。**
为原域调好的默认值（这里是"PubMed 一定在场"）在换域时会集体失效，
而失效的方式往往是沉默的。
