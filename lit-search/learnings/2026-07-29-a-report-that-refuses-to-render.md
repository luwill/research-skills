# 让报告在数字对不上时拒绝出图

**问题**：PRISMA 流程图是系统综述的核心证据。但它由多个环节的计数拼成，
任何一处丢了记录，出来的图仍然"看起来完全正常"——读者没有任何办法从报告本身
发现它是错的。

## approach

1. **把自洽关系写成断言，而不是写进文档。** 三条恒等式：
   识别 − 去重 = 规范记录；窗口判定之和 = 规范记录；筛选各类之和 = 筛选输入。
   任何一条不成立就抛异常，`lit report` 退出码非 0，**不产出文件**。
2. **让检查跑在真实数据上，当场就抓到了东西。** 首次生成时识别数 18,962，
   但语料里明明有整卷补全的 670 条。根因是那一步自己写了采集循环，
   没把结局写进 manifest，而识别数是按 manifest 统计的。
3. **改统计口径到"唯一真相"。** 识别数改为按**实际落盘的逐源记录**统计——
   那些文件是去重的输入，也就是下游一切数字的来源。按"过程记录"（manifest 结局）
   统计，就总有某个新加的阶段会忘记记账。
4. **顺手消掉重复实现。** 把整卷补全改走与滚雪球相同的并入函数。
   同一件事有两份实现，迟早有一份忘记记账。
5. **没做的事不画。** 筛选没跑时，流程图停在"进入标题摘要筛选"，
   并写明"窗口内记录数不是纳入研究数"。

## 判断取舍

- **没有给"不自洽"留一个 `--force` 出口。** 一旦有出口，赶时间的人一定会用，
  然后那份图会被贴进论文。宁可让命令失败。
- **证据表没有猜方法/数据集/指标。** 那些要读全文才知道，标题摘要阶段拿不到，
  统一标"需全文提取"。从标题里猜一个填上去，会让整张表看起来完整而实际不可信。
- **Zotero 推送没有放进 CLI。** CLI 只出 `zotero_dois.txt`，推送交给会话层的 MCP。
  同时**不给没有 DOI 的记录编造标识符**——漏推一条可以人工补，
  推错一条会污染文献库。
- **`lit update` 宁可不做。** 滚动窗口要么是新协议版本（不能与旧 run 合并），
  要么依赖各源的"索引日期"过滤——而 PubMed/OpenAlex 有、Europe PMC/arXiv 没有，
  混着用就是跨源不一致的静默少召回。半对的增量比没有增量危险。

## 可复用的规则

**当一个产物由多个环节的数字拼成时，把环节之间的恒等式写成会让程序失败的断言，
并且不留绕过的开关。** 汇总产物的危险不在于算错，而在于算错了也看不出来。

推论：**统计口径要盯住数据流的"唯一真相"，不要盯住过程记录。**
过程记录会漏，因为每加一个新路径都得有人记得去写；而数据本身漏不掉——
下游正是从它算出来的。
