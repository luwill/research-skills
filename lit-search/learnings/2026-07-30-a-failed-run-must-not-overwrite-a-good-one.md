# 跑砸的一轮，绝不能覆盖跑成的一轮

**问题**：一轮 15,425 条记录的 LLM 筛选，1,234 个请求里 359 个因连接错误失败，
58% 的记录只拿到一个通道的判定。补跑时又撞上余额耗尽，718 个请求全灭——
而那次全灭**仍然写出了一个新轮次**，里面 0 条判定，直接遮蔽掉上一轮的 15,375 条。

## approach

1. **先确认失败是可见的。** 安全网起作用了：漏判的记录进人工队列，
   没有被当成"这批没有相关文献"。这条最重要——如果失败是静默的，
   后面所有分析都建立在假数字上。
2. **认识到真正缺的是断点续跑。** 29% 的瞬时失败不该让两小时和 $4.77 全部作废。
   这和采集侧早就有的 `--resume` 是同一个教训，只是筛选这条路上没吸取。
3. **续跑的判据要选对。** 是"这条记录**在这个通道**有没有判定"，
   不是"这条记录进没进人工队列"。通道分歧和低置信度是**已经判过**的结论，
   重跑它们既浪费钱，也会把一个本该由人裁定的分歧变成掷第二次骰子。
4. **判据需要的信息，之前没有存。** 判定里没有通道号，
   "通道 0 缺判"和"通道 1 缺判"长得一模一样。补了 `channel` 字段，
   并且**由驱动层盖**——通道是请求的属性，让模型填只会多一个出错的地方。
5. **给旧数据一条迁移路径。** 加字段后旧判定全无通道号，
   按位置归位（`merge_verdicts` 是按通道顺序追加的，数量齐了时第 i 个就是通道 i），
   救回 42% 已花的钱。数量不齐时不猜，整条重判。
6. **补上"退步就拒绝写入"。** 新一轮判定数少于上一轮 = 这次跑砸了，
   不写、保留上一轮、非零退出。

## 判断取舍

- **没有把 58% 漏判的那一轮拿去出 PRISMA。** 那 373 篇"纳入"不是筛出来的结果，
  是只有 42% 记录过了双通道的结果。报告一旦印出来，就没人知道它错在哪。
- **迁移时宁可多花钱也不猜通道。** 猜错会让一条记录拿着两份来自**同一视角**的
  判定，双通道就名存实亡——而它看起来和真的双通道判定完全一样。
- **并发从 16 降到 6（续跑用 4）。** 连接错误几乎全来自并发过高。
  慢一点远比"跑完了但 58% 没判"划算。
- **续跑的成本估算只估待补部分。** 续跑却报全量价钱，
  等于让人按一个不会发生的数字做决定。

## 可复用的规则

**任何"最新的覆盖之前的"存储结构，都必须能拒绝一次退步的写入。**
轮次、版本、快照、缓存——只要读取方只认最新的那个，写入方就必须回答
"这次比上次好吗"，答不上来就别写。

推论一：**断点续跑所需的信息，必须在第一次跑的时候就存下来。**
事后想补，要么补不出来（信息已丢失），要么只能靠猜——而猜出来的东西
和真的长得一样，这才是最危险的地方。

推论二：**长任务的失败率是设计参数，不是意外。** 一个跑两小时、
发上千个请求的任务，必然会有部分失败。没有续跑能力的长任务，
等于把"全部成功"当成了前提。
